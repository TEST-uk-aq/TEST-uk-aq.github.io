# Isolated historical JSON comparison viewer

Extends the existing pilot; normal pages/routes and shared chart modules are unchanged. Requires the companion Ops finite-configuration protocol (catalog v2, publication v3, observation/AQI payload v2), private precomputed Worker and explicitly activated authenticated proxy. No deployment or functional/CPU acceptance is implied by this source.

Open /compressed-chart-history-test/ with environment=APPROVED_ENVIRONMENT and, when cross-origin, cache_base=APPROVED_CACHE_ORIGIN/api/aq. The existing session-cookie/Turnstile helper supplies authentication. Environment is explicit and must match every experimental response; cache_base otherwise uses the existing same-origin /api/aq configuration. No endpoint, network ID, storage name, account, station, dates or TEST/LIVE values are embedded in application code. The protected catalog supplies only finite browser-safe identities/ranges/publication digests. Its operator configuration remains private. Missing/disabled/invalid configuration produces a visible error; there is no normal/Parquet fallback from JSON failure.

Controls select normal canonical or precomputed mode, station, genuinely configured pollutant and explicit 24h/seven-day/month/90-day views. No missing IDs/coverage are fabricated. Source/Refresh replace the single active chart context; station/range changes reuse it, and pollutant changes use the shared pollutant-context owner and replacement API. Existing controller/cache/normaliser/renderer and cancellation/settlement rules remain canonical. There is no browser AQI or D3 fork.

An immutable catalog publication frontier is captured for the comparison. All months of one sample share the same publication/source/algorithm identity. Requests and raw-byte digest checks reject conflicting revisions. Transport objects are keyed by environment/configuration/sample/publication/month/part, with shared pending fetch/decode, independent consumer cancellation and bounded reuse (20 retained objects / 64 MiB decoded bytes, up to six additional in-flight objects; individual raw object cap 16 MiB). This is transport reuse, not a second chart-state cache. Old graph/request completion cannot commit into the new context. A changed selector is an explicit 409/refusal until Refresh discovers the new frontier; no mixed revisions are served.

JSON current-head loading is bounded to the last 24h; the shared controller progressively requests older chunks. Only intersecting months are fetched, then decoded objects are reused across daily/weekly chunk requests. Month-end inclusive endpoints may require a genuine next-month fragment; other months are not prefetched for a 24h view. Refresh obtains a no-store authenticated catalog and recreates publication-aware caches. The proxy remains no-store; long-lived HTTP/CDN caching and automatic polling are not claimed or enabled.

Observation/AQI source completeness and evaluated blank statuses remain distinct. Raw observations retain physical identities, provenance, multiplicity and precision; the shared renderer/normaliser applies the same display semantics as normal charts, including existing negative-value filtering and timestamp merging. AQI availability counts are diagnostics, not an all-hours-complete requirement. A separate AQI transport/identity failure can remain local while valid observations are usable; a missing immutable counterpart fails the Worker pair gate.

Diagnostics record request IDs, public publication pins, request counts/known compressed bytes, parse and identity-check time, normalisation, shared cache commits, rendering, first useful line and observation/part settlement hooks. Part settlement marks observed normalised response coverage plus a shared cache commit; it is not a correctness/freshness claim, and completeness must be read independently. Cached repeats may settle without new full-range response markers. Browser timings are never presented as Cloudflare CPU; real per-route CPU/error telemetry is required in P2. Records are capped at 1,500 and display updates are frame-coalesced to bound instrumentation overhead. Cross-origin transfer timing/CPU/memory can be unknown.

Deployment/evaluation/rollback and Chat-mode authoritative-documentation handover are in the companion Ops scripts/compressed_chart_history/STAGE_2B.md. Ops must supply the new protocol before this viewer is evaluated. The website PR changes only this isolated viewer and exact original snapshots under Archive/2026-10-25/compressed-chart-history-test/. No workflow, normal chart module, Sensor.Community aggregation, default chart source or LIVE repository changes.
